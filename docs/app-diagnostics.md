# 앱 실행 정보와 제한된 로그

배포 관리 화면에서 본인 앱의 최근 CPU·메모리 관측값, 실제 컨테이너 상한, 재시작 횟수를 확인한다. 지표가 없거나 오래됐거나 조회가 실패하면 측정 대기로 표시한다. 알 수 없는 값을 0으로 표시하지 않는다. CPU는 최근 5분 rate, 메모리는 working set이며 실시간 보장·peak 측정이 아니다.

로그는 버튼을 눌러 요청할 때만 읽는다. 현재 활성 저장소와 요청자의 GitHub 계정을 서버에서 확인하며 접근 허용이 해제된 계정도 거부한다. 최신 교체 Pod를 우선하고 초기화 실패 시 해당 init 컨테이너를 선택한다. 현재 로그의 최근 1시간·최대 100줄·16KiB만 반환하고 이전 Pod 전체 이력이나 실시간 스트리밍은 제공하지 않는다. HTTP 응답은 `no-store`이며 브라우저 저장소에 보관하지 않는다.

환경변수의 4자 이상 값, 일반 인증 헤더·쿠키·JWT·비공개 키·연결 URL 인증값을 가린다. 환경변수 조회 실패 시 원문 로그를 반환하지 않는다. 임의의 애플리케이션 로그에 든 모든 개인정보·짧은 비밀·변형된 토큰까지 탐지한다는 보장은 하지 않으며 화면에도 공유 전 확인을 안내한다. React 텍스트로 렌더링해 로그의 HTML을 실행하지 않는다. 감사 로그에는 조회 주체와 앱만 남기고 내용·환경변수 값은 남기지 않는다.

## 기존 앱 권한 이행

새 등록은 템플릿의 namespace Role에 `get pods/log`만 추가한다. 기존 앱은 관리 호스트에서 아래 계획을 먼저 확인하고 `--execute`로 이행한다.

```sh
sudo python3 backfill-diagnostics-access.py
sudo python3 backfill-diagnostics-access.py --execute
```

현재 Argo Application이 있고 사용자 tenant 라벨이 맞는 namespace만 대상으로 별도 Role·RoleBinding을 생성한다. 기존 동명 자원은 소유 라벨과 권한이 정확히 일치해야 재사용한다. 전체 클러스터 로그 접근이나 실행 권한은 주지 않는다. 사용자 앱/배포 저장소를 수정하지 않으며 기존 GitOps Role도 덮어쓰지 않는다. namespace 삭제 시 이행 자원도 함께 사라진다. 새 등록부터는 일반 템플릿 권한으로 동작한다.

권한을 새로 추가하는 운영 이행이므로 적용 대상·시각·`kubectl auth can-i get pods/log --as=system:serviceaccount:swkoo:swkoo-backend -n <대상>` 결과를 기록한다. 다른 이용자의 실제 로그를 확인 목적으로 수집하지 않는다.
