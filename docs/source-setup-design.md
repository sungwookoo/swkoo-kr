# 배포 등록 시 사용자 저장소 변경 정책

## 사용자 흐름

1. 배포 사전 점검 후 `GET /deploy/setup?repo=owner/name`으로 대상 main 브랜치·commit·파일별 현재/제안 내용을 조회한다. 조회는 저장소를 수정하지 않는다.
2. Dockerfile과 `.github/workflows/build.yml`을 분류한다.
   - 없음: 동의 후 main에 직접 생성한다.
   - 현재 템플릿과 동일함(CRLF 차이 제외): 기존 파일을 그대로 유지한다.
   - 다름: 직접 덮어쓰지 않는다. 사용자 요청으로 별도 브랜치와 초안 PR을 생성한다.
3. 차이가 있다는 사실은 기존 파일이 잘못됐거나 동작하지 않는다는 판정이 아니다. 커스텀 설정의 의미·호환성을 자동 검증하지 않는다. 사용자가 변경 내용을 검토하고 병합할지 결정한다.
4. PR 생성만으로 신규 앱 배포를 등록하지 않는다. 병합 후 사용자가 파일 상태를 다시 조회하고 별도로 배포에 동의한다. 병합 결과가 템플릿과 다르면 자동 호환 판정 없이 다시 검토 대상으로 표시한다.
5. 이미 배포 중인 앱은 기존 GitHub Actions/이미지 업데이트 설정에 따라 병합 시 자동 배포될 수 있다. 이 사실을 화면과 PR에서 안내한다.

## 동의·보호 장치

- 등록과 PR 요청 모두 로그인·allowlist·본인 소유 저장소 검사를 적용한다. 현재 지원 브랜치는 main이다.
- 서버는 소스 SHA·대상 파일 현재 내용·제안 내용을 묶은 digest를 재계산한다. 클라이언트는 검토한 digest와 `source-setup-v1` 동의를 전송해야 한다. 화면에서만 버튼을 막는 방식이 아니다.
- 기존 등록 API도 동의/digest가 없으면 쓰기 전에 거부한다. 이전 클라이언트는 화면을 새로고침해야 한다.
- 누락 파일 직접 커밋은 Git 참조를 읽을 때 검토한 SHA인지 재확인한다. ref 업데이트는 force=false로, 중간에 브랜치가 전진했으면 덮어쓰지 않는다.
- 기존 파일이 하나라도 다르면 누락 파일을 포함한 전체 변경을 PR에 제안한다. PR 요청 전에 main에 일부 파일을 먼저 쓰지 않는다.
- PR 브랜치 이름은 검토 digest로 결정하므로 재시도 시 동일 PR을 반환한다. 다른 열린 설정 PR이 있으면 먼저 검토하도록 안내한다. 수정된 제안 브랜치를 덮어쓰거나 닫힌 PR을 자동 재생성하지 않는다.
- 일반 파일만 읽으며, 200KB 초과 파일·불완전한 Git tree 조회는 ‘파일 없음’으로 취급하지 않는다. 파일 읽기 실패도 생성 허가가 아니다.
- 소스 조회 토큰은 해당 repo의 contents/read·pull_requests/read, 직접 생성은 contents/write·workflows/write, PR 생성은 여기에 pull_requests/write를 추가한다. 사용자 저장소 밖의 repo 권한을 작업 토큰에 요청하지 않는다.
- 소스 파일 전문은 서버에 새로 영구 저장하지 않는다. 생성 PR은 GitHub에 남으며 사용자가 관리한다. 성공한 등록의 검토 SHA·digest·파일별 동작과 PR 요청을 감사 로그로 남긴다.

## 결과·실패 처리

- 성공 시 소스 commit 링크와 배포 진행상황 진입 버튼을 표시한다. 기존 파일을 모두 유지한 경우 소스 commit은 확인한 기존 revision이다.
- 소스 생성 후 매니페스트/등록 단계 실패 시 완료된 단계와 소스 commit 링크를 반환한다. 이미 적용된 파일을 자동 삭제하거나 되돌리지 않는다.
- 소스 커밋 요청의 결과를 확인하지 못한 경우 성공/미변경을 단정하지 않고 저장소 재확인을 안내한다. URL 예약은 유지될 수 있다.
- PR은 앱 빌드·테스트를 수행하지 않은 초안이다. 자동 병합하지 않는다. 계정별 요청 직렬화나 신규 배포 작업 큐를 이번 변경에 추가하지 않는다.

## 검증

- 파일 없음/일치/차이, 동의 누락, 검토 digest 변경, 브랜치 전진, 읽기 불완전, PR 재시도 경계를 모의 GitHub API로 검사한다.
- 배포 서비스에서 동의 없이 URL 예약/소스 쓰기/매니페스트 등록을 수행하지 않는지, PR 요청이 배포 등록으로 이어지지 않는지 검사한다.
- 브라우저에서 현재/제안 파일 내용, 두 동작의 동의, 병합 후 재조회, 등록 성공 링크, 부분 실패 안내를 검사한다.
- 사용자 앱 저장소에 테스트용 커밋이나 PR을 만들지 않는다.
